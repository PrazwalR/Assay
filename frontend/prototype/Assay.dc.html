Spoofing resistance is economic, not architectural.

The fee is quoted from a quantity the trader must pay to fake. Trading away from the reference to earn the low quote means forgoing the drift itself. Flow that captures nothing has negative drift and is quoted below the base fee — that sign is the entire per-swap discrimination.

Introduction

Assay is a Uniswap v4 hook that prices adverse selection per swap rather than per pool. Since v4, beforeSwap can return a fee for one specific swap. Assay uses that.

It is a pricing mechanism, not an access-control mechanism. It never blocks, never censors, and never takes custody of swap principal.

Status
Unaudited, and never having held value. Base Sepolia only. The adverse-selection gate does not currently pass — the mechanism is implemented and deployed; the evidence that it improves liquidity-provider outcomes is not established.

The problem

Every dynamic-fee hook shipping today sets the fee from volatility. Volatility is a property of the market, so it is identical for everyone in a block: a retail swap and a top-of-block arbitrage pay the same rate, though one is the liquidity provider's entire revenue and the other is their entire loss.

Assay's fee is a share of the price drift a swap captures against a cached reference, signed by direction — so two swaps in the same block trading opposite directions are quoted differently. Measured at 100 bp against 1 bp, same block, same pool.

The fee formula

The mechanism is the no-arbitrage band, not a fitted model. An arbitrageur profits only while the drift they capture exceeds what they pay for it, so charging a fraction of that drift takes back part of the extraction while leaving the trade worth doing.

// FeeBlend.sol — _rawQuotedPips
drift     = clamp(signedMispricingTicks, ±200_000)
scaled   = drift × 100 × captureShareBps
surcharge = ⌈ scaled / 10_000 ⌉  // toward +∞
quoted   = baseFeePips + surcharge
fee      = clamp(quoted, minFeePips, maxFeePips)

Rounded toward positive infinity so the quoted fee is never below the exact value. Solidity's signed division truncates toward zero, which lowers the fee on the capturing side — the toxic side — and is therefore the liquidity-adverse direction.

One tick is one basis point of price, and fees are quoted in hundredths of a basis point, so a tick of drift is worth 100 pips of fee. At a 10% capture share, each tick of drift adds 10 pips: the cap is reached at 950 ticks.

Why 1,000 bps and not 5,000

The capture share is calibrated conservatively. calibrate_capture_share.py searches for the share with the least bad worst case across two independent windows of flow and the full plausible range of uninformed fee elasticity — rather than the share scoring highest under one assumption. Worst case at 1,000 bps is −$935 over three days on $317M of volume; the previous 5,000 had a worst case thirteen times larger for about three times the upside.

The elasticity is bounded rather than measured. Uniswap runs ETH/USDC at both 5 bp and 30 bp with real volume at each, which rules out the high end; estimating it from cross-tier volumes would tighten this considerably.

The fee-cap overflow

An LP fee above a few percent is not a sane pool parameter regardless of what the formula asks for, so quote clamps. On an extreme dislocation the discarded remainder is recovered as an absolute amount and routed straight to in-range liquidity providers.

// afterSwap
overflowPips = raw − maxFeePips  // bounded at 1_000_000
poolManager.donate(amount)    // no escrow, no owner
return +int128(amount)       // nets to zero, unspecified currency

v4 constraints

These constraints shape the code. Integrations that ignore them break in ways that are not obvious from the interface.

Permissions live in the address, not in code
The last 14 bits of the deployed address carry the flags, and the address is CREATE2-mined. Declaring a flag without implementing its callback bricks the pool; implementing a callback whose flag is absent means it is silently never called. Flags in use: BEFORE_INITIALIZE, AFTER_INITIALIZE, BEFORE_SWAP, AFTER_SWAP, AFTER_SWAP_RETURNS_DELTA — mask 0x30C4.
Dynamic fee handshake
The pool must be initialised with key.fee == DYNAMIC_FEE_FLAG (0x800000). The per-swap override returns fee | OVERRIDE_FEE_FLAG (0x400000) as the third return value of beforeSwap. Fee units are hundredths of a bip; MAX_LP_FEE is 1,000,000.
sender is the router, never the trader
It is never a user identity. Any logic treating it as one is a critical finding — which is why the quote is derived from the drift a swap captures and not from who submitted it.
The zero-hookData path must work
If a swap cannot execute without custom hookData, aggregators cannot route to the pool. Assay requires none.
One hook serves many pools
All state is keyed by PoolId. Any cross-pool aggregate state is a critical finding, and multi-pool isolation is fuzzed as an invariant.
Everything in the callbacks is on the hot path
Three reachable paths are budgeted separately: ordinary swap 14,572 gas, block-boundary refresh 30,901 plus a ~16,500 live-feed premium, extreme dislocation 48,582. A live Chainlink read alone measures 20,774 gas, which is why the reference is cached.

Invariants

Ranked by consequence. The invariant suite fuzzes the ordering itself — swaps, liquidity changes, block advances and reference price events in any sequence — with fail_on_revert = true, so a revert anywhere aborts the run rather than being absorbed.

01 beforeSwap never reverts for any well-formed swap — any pool state, uninitialised or stale oracle, zero liquidity, extreme ticks. A revert here bricks the pool. live
02 f_min ≤ quotedFee ≤ f_max ≤ MAX_LP_FEE for all inputs. live
04 All hook deltas settle; NonzeroDeltaCount reaches zero. live
05 No cross-pool state contamination. live
08 Rounding is directional and consistent, always in the LP's favour. live
09 LP liquidity is never trapped. There is no hook on add or remove liquidity, structurally. live
03 · 06 · 07 · 10 Not applicable: no rebate ledger, no posterior probability, no attestations, and variance is no longer computed on the swap path. n/a

156 tests. Seven stateful properties at 8,192 calls each. Four of the five real bugs found in this project came from state interactions across calls — which is what this reaches and a fixed test sequence does not.

Risk & known gaps

Stated so silence is not mistaken for coverage.

No deviation cap against a pool TWAP
A compromised feed within its staleness window mis-prices fees, bounded only by maxFeePips. The threat model lists a cap as a mitigation; it is not implemented.
No pool allowlist in beforeInitialize
What exists instead is a currency-pair binding: the hook refuses any pool whose currencies do not match the pair its oracle declares. Both halves are covered by UnboundPool.t.sol.
The adverse-selection gate does not pass
The mechanism is implemented and deployed; the evidence that it improves LP outcomes is not established. See P0-GATE-RESULT.md, which reports the failure and why, rather than the earlier claim it replaces.

What is not built

The original design described a posterior probability over six microstructure signals, a rebate ledger, and router attestation. Most of that is not built, and the parts that were built and measured were removed rather than left to bill every swap for nothing.
